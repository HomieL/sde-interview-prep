    Fundamentals

    Big O notation

    Big O describes how the work an algorithm does grows as its input grows. Drag the slider to watch ten common growth rates pull apart, then use the cards below for a code pattern you’ll recognize for each.

    1,000

    Bars use a log scale and fill at 10¹² steps; striped bars are off the chart. Time assumes roughly 10⁸ simple steps per second, a common rule of thumb for interview judges. For n·m, m is held at 1,000.

    O(1)Constant

    The work doesn’t depend on n at all. Reading one slot of an array, or a hash-map lookup on average, costs the same whether the collection holds ten items or ten million.

    def last_item(items):
    return items[-1]          # direct index

def has_seen(seen: set, x):
    return x in seen          # average-case hash lookup

    Spot it when

    • You touch a fixed number of elements.
    • Array index, hash get/set, stack push/pop.
    • Arithmetic on a few variables.

    n = 1,000,000 → 1 step

    O(log n)Logarithmic

    Every step throws away a constant fraction of what’s left, usually half. Doubling n adds just one more step.

    def find(sorted_nums, target):
    lo, hi = 0, len(sorted_nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if sorted_nums[mid] == target:
            return mid
        if sorted_nums[mid] < target:
            lo = mid + 1         # drop left half
        else:
            hi = mid - 1         # drop right half
    return -1

    Spot it when

    • The search space halves each iteration.
    • A loop variable doubles or halves: i *= 2.
    • Walking root-to-leaf in a balanced tree; heap push/pop.

    n = 1,000,000 → ≈ 20 steps

    O(√n)Square root

    The loop stops once a value squared passes n. It shows up mostly in number problems like factors and primes.

    def divisors(n):
    out = []
    i = 1
    while i * i <= n:          # stop at √n
        if n % i == 0:
            out.append(i)
            if i != n // i:
                out.append(n // i)   # paired divisor
        i += 1
    return out

    Spot it when

    • Loop condition looks like i * i <= n.
    • Divisors come in pairs, so you only check up to the middle.
    • Trial-division primality checks.

    n = 1,000,000 → 1,000 steps

    O(n)Linear

    You look at each element a constant number of times. Twice the input means twice the work.

    def max_gap(nums):
    best = 0
    for i in range(1, len(nums)):
        best = max(best, nums[i] - nums[i - 1])
    return best

# Two pointers is still O(n): together
# they make at most n moves.

    Spot it when

    • One pass (or a few separate passes) over the input.
    • Building a hash map or prefix sums.
    • Sliding window or two pointers where each pointer only moves forward.

    n = 1,000,000 → 1,000,000 steps

    O(n log n)Linearithmic

    A log n cost paid n times, or n work done on each of log n levels. This is the floor for comparison-based sorting.

    import heapq

def meetings_fit(intervals):
    intervals.sort()                 # n log n
    for a, b in zip(intervals, intervals[1:]):
        if b[0] < a[1]:              # n
            return False
    return True

def drain(nums):                   # n pushes + n pops,
    h = []                          # each log n
    for x in nums: heapq.heappush(h, x)
    return [heapq.heappop(h) for _ in nums]

    Spot it when

    • You sort first, then do a linear pass.
    • Merge sort, heap sort, average quicksort.
    • n heap operations, or n binary searches.

    n = 1,000,000 → ≈ 20,000,000 steps

    O(n·m)Two independent sizes

    When two inputs can vary separately, give each its own letter. A grid with n rows and m columns, or comparing two different strings, costs n·m.

    def count_land(grid):
    total = 0
    for row in grid:              # n rows
        for cell in row:          # m columns
            if cell == "1":
                total += 1
    return total

# Edit distance / LCS tables are also n·m.

    Spot it when

    • Nested loops over two different collections.
    • 2D grids, BFS/DFS over every cell.
    • DP tables indexed by two strings.

    Don’t collapse it to n² unless you know n and m are the same size.

    O(n²)Quadratic

    Nested loops over the same input. Checking every pair is about n²/2 steps, which still simplifies to n².

    def has_duplicate(nums):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return True
    return False

# Two loops one after the other: n + n = O(n).
# One loop inside the other:     n × n = O(n²).

    Spot it when

    • A loop inside a loop, both over n.
    • Bubble, insertion, selection sort.
    • Hidden costs: list.insert(0, x) or x in some_list inside a loop.

    n = 10,000 → 100,000,000 steps

    O(n³)Cubic

    Three nested loops over n. Fine for a few hundred elements, painful beyond that.

    def matmul(A, B):
    n = len(A)
    C = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            for k in range(n):
                C[i][j] += A[i][k] * B[k][j]
    return C

    Spot it when

    • Triple-nested loops: all triplets, naive matrix multiply.
    • Floyd–Warshall all-pairs shortest paths.
    • Interval DP that tries every split point.

    n = 500 → 125,000,000 steps

    O(2ⁿ)Exponential

    Each element gets a yes/no choice, so the number of outcomes doubles with every element you add. Generating subsets is the classic case.

    def subsets(nums):
    out, pick = [], []
    def go(i):
        if i == len(nums):
            out.append(pick[:])
            return
        pick.append(nums[i]); go(i + 1)   # take it
        pick.pop();           go(i + 1)   # skip it
    go(0)
    return out

# Naive fib(n) = fib(n-1) + fib(n-2) is also
# exponential; memoizing it makes it O(n).

    Spot it when

    • Recursion that branches twice and only shrinks n by 1.
    • Include/exclude decision trees.
    • Brute-forcing every combination or bitmask.

    n = 30 → ≈ 1,000,000,000 steps

    O(n!)Factorial

    Every ordering of n items. The first slot has n choices, the next n−1, and so on. Even n = 12 is about half a billion orderings.

    def orderings(items):
    out = []
    def go(path, left):
        if not left:
            out.append(path)
            return
        for i in range(len(left)):
            go(path + [left[i]], left[:i] + left[i+1:])
    go([], items)
    return out

    Spot it when

    • Generating all permutations, where order matters.
    • Brute-force traveling salesman.
    • Trying every arrangement of seats, tasks or routes.

    n = 12 → 479,001,600 orderings

    Simplifying rules

    • Drop constants. 3n + 7 becomes O(n).
    • Keep the biggest term. n² + n log n + n becomes O(n²).
    • Steps in sequence add: sort then scan is n log n + n = O(n log n).
    • Nested steps multiply: a binary search inside a loop over n is O(n log m).
    • Recursion does about branchesdepth calls, times the work per call.
    • Space counts too: extra memory you allocate plus the deepest recursion stack.

    Input size → target complexity

    Around 10⁸ simple steps is a safe budget for most judges, so the constraint on n hints at the expected solution.

    If n is up toAim forTypical approach
    ~10O(n!)Permutations, brute-force orderings
    ~20–25O(2ⁿ)Subsets, bitmask search, backtracking
    ~500O(n³)Triple loops, interval DP, Floyd–Warshall
    ~5,000O(n²)All pairs, 2D DP
    ~10⁶O(n log n)Sorting, heaps, binary search on the answer
    ~10⁸O(n)One pass, hashing, two pointers
    biggerO(log n) or O(1)Binary search, a math formula

    Things to remember

    • Big O is about growth rate, not speed. An O(1) step with a huge constant can lose to an O(n) loop on small inputs.
    • Unless stated otherwise, Big O means worst case. Say “average” explicitly for hash lookups and quicksort.
    • Library calls aren’t free: sorted() is n log n, slicing copies, and in on a list is linear.
    • Amortized O(1), like appending to a dynamic array, means rare expensive steps average out over many operations.
    • Building a string with += in a loop can quietly become O(n²). Collect the parts and join once.

    Recursion guide

    A recursive function solves a problem by calling itself on a smaller version of the same problem, until it hits a case small enough to answer directly.

    Anatomy of a recursive function

    def total(nums, i=0):
    if i == len(nums):          # base case: nothing left
        return 0
    return nums[i] + total(nums, i + 1)   # smaller problem

def reverse(s):
    if len(s) <= 1:
        return s
    return reverse(s[1:]) + s[0]

    Every recursive function needs

    1. A base case that returns without recursing.
    2. A recursive case that calls itself on smaller input.
    3. Progress: each call must move closer to the base case, or it never stops.

    How to write one: the leap of faith

    1. Say in one sentence what f(x) returns. Example: “depth(node) returns the height of the subtree at node.”
    2. Assume f already works on smaller inputs. Don’t trace the whole call tree in your head.
    3. Use those smaller answers to build the answer for x.
    4. Handle the smallest inputs (empty, single element, None) as base cases.
    def depth(node):
    if node is None:
        return 0
    return 1 + max(depth(node.left), depth(node.right))

    The call stack

    Each call gets a stack frame holding its arguments and local variables, which is freed when it returns. Memory used is proportional to the deepest chain of calls alive at once, not the total number of calls.

    • Python’s default recursion limit is about 1,000 frames. Raise it with sys.setrecursionlimit, or convert to iteration for deep inputs like a linked list of 10⁵ nodes.
    • Python does not optimize tail calls, so a tail-recursive function still uses O(depth) stack.

    Shapes of recursion

    ShapeCalls per frameExampleTimeSpace
    Linear1, shrinks by 1factorial, sum of listO(n)O(n)
    Halving1, halvesrecursive binary search, fast powerO(log n)O(log n)
    Divide and conquer2, halvesmerge sortO(n log n)O(n)
    Tree traversal2, per childDFS on a binary treeO(n)O(h)
    Branching2, shrinks by 1naive Fibonacci, subsetsO(2ⁿ)O(n)
    Permutingn, n−1, …all orderingsO(n·n!)O(n)

    Time ≈ number of calls × work done in each call. Space ≈ maximum depth × memory per frame, plus anything you build.

    Memoization: stop repeating work

    from functools import cache

def fib_slow(n):                # O(2^n)
    if n < 2:
        return n
    return fib_slow(n - 1) + fib_slow(n - 2)

@cache
def fib(n):                     # O(n)
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

    If the same arguments show up in many branches, cache the result the first time. Each distinct state is then computed once, so time becomes number of states × work per state.

    This is top-down dynamic programming. Arguments must be hashable, so pass tuples instead of lists.

    Turning recursion into a loop

    def preorder(root):
    out, stack = [], [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.right: stack.append(node.right)
        if node.left:  stack.append(node.left)   # left runs first
    return out

    Any recursion can be rewritten with an explicit stack: push what you would have recursed on, pop to process. Push children in reverse order to keep the same visiting order.

    Do this when input depth could exceed the recursion limit.

    Nested loop complexity

    “Two loops means n²” is right often enough to be dangerous. Count how many times the innermost line actually runs.

    Quick reference

    Loop shapeInner line runsBig O
    Two loops one after anothern + nO(n)
    Inner loop over all n, inside outer over nn · nO(n²)
    Inner starts at i (pairs, triangle)n(n−1)/2O(n²)
    Outer over n, inner over mn · mO(n·m)
    Outer over n, inner halvesn · log nO(n log n)
    Outer doubles, inner runs up to i1 + 2 + 4 + … + n ≈ 2nO(n)
    Outer over i, inner steps by in/1 + n/2 + n/3 + …O(n log n)
    Inner pointer never resetsat most n moves totalO(n)
    Inner runs a constant k timesk · nO(n)

    The triangle: still quadratic

    for i in range(n):
    for j in range(i + 1, n):
        check(i, j)

    The inner loop runs n−1, then n−2, down to 0 times. That sums to n(n−1)/2, which is half of n², and halving is a constant factor. Skipping repeated pairs makes code faster, not lower in Big O.

    Gotcha: the doubling outer loop

    i = 1
while i <= n:
    for j in range(i):     # runs i times
        work()
    i *= 2

    It looks like n log n, since the outer loop runs log n times. But the inner loop runs 1, 2, 4, …, n times, and that geometric series sums to under 2n. The total is O(n). Always add up the inner counts instead of multiplying the worst inner count by the outer count.

    Gotcha: the harmonic loop

    for i in range(1, n + 1):
    for j in range(i, n + 1, i):   # multiples of i
        mark(j)

    The inner loop runs n/i times. Summing n/1 + n/2 + … + n/n gives n times the harmonic series, about n ln n. The total is O(n log n). This is the shape of the Sieve of Eratosthenes.

    Gotcha: the pointer that never goes back

    left = 0
for right in range(n):
    window.add(s[right])
    while too_big(window):
        window.remove(s[left])
        left += 1

    A while inside a for, yet it’s O(n). left only moves forward and can move at most n times over the whole run, so the inner loop’s total work across all iterations is n. This is amortized analysis, and it’s why sliding window and two pointers are linear.

    Hidden loops

    One line of code can be a loop. Inside another loop, these multiply.

    • x in my_list, my_list.index(x), my_list.count(x): O(n)
    • my_list.insert(0, x), my_list.pop(0): O(n). Use collections.deque.
    • arr[a:b], list(x), s + t: O(length) copy
    • sorted(x), x.sort(): O(n log n)
    • min(x), max(x), sum(x): O(n)
    • Comparing or hashing a string of length L: O(L)

    Hash maps

    A hash map stores key → value pairs. A hash function turns each key into a bucket index, so finding a key takes constant time on average instead of a scan.

    Operations

    OperationPythonAverageWorst
    Insert / updated[k] = vO(1)O(n)
    Lookupd[k], d.get(k, 0)O(1)O(n)
    Membershipk in dO(1)O(n)
    Deletedel d[k], d.pop(k)O(1)O(n)
    Iteratefor k, v in d.items()O(n)O(n)

    The worst case happens when many keys collide into one bucket. In interviews, state “O(1) average” and move on unless asked.

    How it works

    • Hash and mod: index = hash(key) % capacity picks the bucket.
    • Collisions are unavoidable. Chaining keeps a small list per bucket. Open addressing (used by Python’s dict) probes for the next free slot.
    • Load factor = items / capacity. When it gets too high, the table grows (usually doubles) and every key is rehashed. That one resize is O(n), but it’s rare, so inserts are amortized O(1).
    • Keys must be hashable, meaning immutable. Strings, numbers and tuples work; lists, dicts and sets don’t. Convert a list with tuple(lst).

    Patterns

    Seen-before lookup

    def pair_with_sum(nums, target):
    index_of = {}
    for i, x in enumerate(nums):
        if target - x in index_of:
            return [index_of[target - x], i]
        index_of[x] = i

    Trade O(n) memory for turning an O(n²) pair search into one pass. Ask “what value would complete the answer?” and look it up.

    Group by a canonical key

    def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups[tuple(sorted(w))].append(w)
    return list(groups.values())

    Map every item to a signature that’s equal for items in the same group: a sorted string, a letter-count tuple, a normalized shape.

    Prefix sum + counts

    def subarrays_summing_to(nums, k):
    count = {0: 1}
    running = ans = 0
    for x in nums:
        running += x
        ans += count.get(running - k, 0)
        count[running] = count.get(running, 0) + 1
    return ans

    A subarray sums to k when two prefix sums differ by k. Count earlier prefixes as you go. Works with negative numbers, unlike sliding window.

    Pitfalls

    • Changing a dict’s size while iterating over it raises an error. Iterate over list(d) instead.
    • Dicts keep insertion order (Python 3.7+); sets have no reliable order.
    • Hashing a long string key costs O(length), which counts if keys are big.

    Data structures

    Trees

    A tree is a set of nodes where each node has one parent (except the root) and no cycles. Most interview trees are binary: each node has at most a left and a right child.

    Vocabulary

    Root / leaf
    The top node / a node with no children.
    Depth / height
    Edges from the root down to a node / longest path from a node down to a leaf.
    Binary search tree
    Every value in the left subtree is smaller than the node, every value in the right is larger.
    Balanced
    Height stays O(log n). AVL and red-black trees rebalance to guarantee it.
    Complete
    Every level full except possibly the last, filled left to right. Heaps are complete trees.
    class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val, self.left, self.right = val, left, right

    Depth-first traversals

    def walk(node, out):
    if not node:
        return
    # preorder:  out.append(node.val) here
    walk(node.left, out)
    # inorder:   out.append(node.val) here
    walk(node.right, out)
    # postorder: out.append(node.val) here
    • Preorder (node, left, right): copying or serializing a tree.
    • Inorder (left, node, right): gives a BST’s values in sorted order.
    • Postorder (left, right, node): when a node needs its children’s answers first, like heights or deleting.

    Breadth-first (level order)

    from collections import deque

def levels(root):
    if not root:
        return []
    out, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):     # exactly one level
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        out.append(level)
    return out

    Use BFS for anything “per level”: right-side view, level averages, minimum depth, zigzag order. Snapshotting len(q) before the inner loop is what separates levels.

    The return-a-value template

    def diameter(root):
    best = 0
    def height(node):
        nonlocal best
        if not node:
            return 0
        l, r = height(node.left), height(node.right)
        best = max(best, l + r)     # path through node
        return 1 + max(l, r)        # what parent needs
    height(root)
    return best

    Many tree problems follow this shape: recurse into both children, combine their results, update a global answer, and return what the parent needs. The value you return and the answer you track are often different things.

    Binary search trees

    def search(node, target):
    while node and node.val != target:
        node = node.left if target < node.val else node.right
    return node

def is_bst(node, lo=float("-inf"), hi=float("inf")):
    if not node:
        return True
    if not lo < node.val < hi:
        return False
    return is_bst(node.left, lo, node.val) and is_bst(node.right, node.val, hi)

    Search, insert and delete cost O(h): O(log n) when balanced, O(n) when the tree degrades into a line.

    To validate a BST, pass down the allowed range. Checking only a node against its direct children misses violations deeper down.

    Complexity

    • Visiting every node, by DFS or BFS: O(n) time.
    • DFS space: O(h) for the recursion stack, from log n balanced to n skewed.
    • BFS space: O(w), the widest level, up to about n/2 for a complete tree.

    Heaps

    A heap always gives you the smallest (min-heap) or largest (max-heap) item quickly, while letting you keep adding items. It’s the standard way to build a priority queue.

    How it’s stored

    A heap is a complete binary tree kept in a plain array. Every parent is ≤ its children in a min-heap, so the minimum sits at index 0. Siblings are not ordered.

    • Children of i: 2i + 1 and 2i + 2
    • Parent of i: (i - 1) // 2
    OperationCost
    Peek at minO(1)
    Push (sift up)O(log n)
    Pop min (sift down)O(log n)
    Heapify a listO(n)
    Find arbitrary itemO(n)

    Python’s heapq

    import heapq

h = [5, 1, 8, 3]
heapq.heapify(h)              # in place, O(n); h[0] == 1
heapq.heappush(h, 2)
smallest = heapq.heappop(h)

# heapq is min-only. For a max-heap, store negatives:
heapq.heappush(maxh, -x);  largest = -heapq.heappop(maxh)

# Priorities with payloads: tuples compare item by item.
heapq.heappush(tasks, (priority, order_added, task))   # tiebreaker avoids comparing tasks

heapq.nsmallest(3, nums);  heapq.nlargest(3, nums, key=len)

    Patterns

    Keep the k largest with a size-k min-heap

    def kth_largest(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)      # drop the smallest
    return h[0]

    The heap’s root is the weakest of your current top k, so it’s the one to evict. O(n log k) time, O(k) space.

    Merge k sorted lists

    def merge_sorted(lists):
    h = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(h)
    out = []
    while h:
        val, i, j = heapq.heappop(h)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return out

    The heap holds one “front” item per list. O(N log k) for N total items.

    Running median with two heaps

    class Median:
    def __init__(self):
        self.lo, self.hi = [], []      # max-heap (negated), min-heap
    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def get(self):
        if len(self.lo) > len(self.hi):
            return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2

    The lower half lives in a max-heap and the upper half in a min-heap, kept within one item of each other. The median is at the tops.

    When to reach for a heap

    • “k largest / smallest / closest / most frequent”
    • Repeatedly taking the best next item: task scheduling, meeting rooms, greedy merging
    • Shortest paths with weights (Dijkstra)
    • Merging many sorted streams

    If you only need the extremes once, sorted() is simpler. Heaps win when items keep arriving or you only need the top k.

    Graphs

    A graph is a set of nodes (vertices) connected by edges. Trees, grids, social networks, road maps and course prerequisites are all graphs.

    Vocabulary

    Directed / undirected
    Edges have a direction (a → b) or go both ways.
    Weighted
    Each edge carries a cost, like distance or time.
    Cycle
    A path that returns to its start.
    DAG
    Directed acyclic graph. Dependencies, build orders.
    Connected component
    A group of nodes all reachable from each other.
    Degree
    Number of edges at a node; in-degree and out-degree for directed graphs.

    DFS: go deep

    def dfs(start, adj):
    seen = {start}
    stack = [start]
    while stack:
        node = stack.pop()
        for nxt in adj[node]:
            if nxt not in seen:
                seen.add(nxt)
                stack.append(nxt)
    return seen

    Use for reachability, counting components, cycle detection, and exploring every path.

    Unlike a tree, a graph can loop back on itself. Without a seen set, traversal can run forever.

    BFS: go wide, find shortest paths

    from collections import deque

def shortest_steps(start, goal, adj):
    q = deque([(start, 0)])
    seen = {start}
    while q:
        node, d = q.popleft()
        if node == goal:
            return d
        for nxt in adj[node]:
            if nxt not in seen:
                seen.add(nxt)          # mark when queued, not when popped
                q.append((nxt, d + 1))
    return -1

    BFS reaches nodes in order of distance, so the first time it reaches the goal is via a shortest path, as long as every edge costs the same. For “minimum steps” on an unweighted graph or grid, BFS is the default.

    Topological sort (Kahn’s algorithm)

    def topo_order(n, edges):              # edge (a, b): a before b
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for a, b in edges:
        adj[a].append(b); indeg[b] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else []   # [] means a cycle

    Orders the nodes of a DAG so every edge points forward. Repeatedly take a node with no remaining prerequisites. If some nodes never reach in-degree 0, there’s a cycle.

    Dijkstra: weighted shortest paths

    import heapq

def dijkstra(src, adj):          # adj[u] = [(v, weight), ...]
    dist = {src: 0}
    h = [(0, src)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist.get(u, float("inf")):
            continue                 # stale entry
        for v, w in adj[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(h, (nd, v))
    return dist

    Always expand the closest unfinished node. Requires non-negative weights. O((V + E) log V) with a heap.

    Union-find (disjoint set)

    parent = list(range(n))
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # path compression
        x = parent[x]
    return x
def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False                    # already connected
    parent[ra] = rb
    return True

    Tracks which nodes are in the same group as edges arrive. Great for “are these connected?”, counting components, and detecting a cycle in an undirected graph (a union that returns False). Near-constant time per operation.

    Complexity

    • BFS and DFS: O(V + E) time, O(V) space.
    • Grid of r × c: V = r·c and E ≈ 4·r·c, so O(r·c).
    • Dijkstra with a heap: O((V + E) log V).
    • Topological sort: O(V + E).

    Grid as an implicit graph

    DIRS = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols:

    Every cell is a node and its 4 (or 8) neighbors are edges. You never build the graph; you compute neighbors on the fly. Mark visited cells in a set, or overwrite the grid if mutating it is allowed.

    Two classic combinations

    LRU cache = hash map + doubly linked list

    from collections import OrderedDict

class LRU:
    def __init__(self, cap):
        self.cap, self.d = cap, OrderedDict()
    def get(self, k):
        if k not in self.d:
            return -1
        self.d.move_to_end(k)
        return self.d[k]
    def put(self, k, v):
        self.d[k] = v
        self.d.move_to_end(k)
        if len(self.d) > self.cap:
            self.d.popitem(last=False)   # evict oldest

    The map finds a key in O(1); the list keeps recency order so the least recently used item is always at one end. OrderedDict is exactly this pair; interviewers may ask you to build the list yourself.

    Indexed priority queue = heap + hash map

    A heap alone can’t find or update an arbitrary item. Pair it with a map from item to position (or use lazy deletion: push the new priority and skip stale entries when popped, as Dijkstra does).

    Insertion sort

    def insertion_sort(a):
    for i in range(1, len(a)):
        cur, j = a[i], i - 1
        while j >= 0 and a[j] > cur:
            a[j + 1] = a[j]       # shift right
            j -= 1
        a[j + 1] = cur
    return a

    Grows a sorted prefix one item at a time. Fast on small or nearly sorted arrays, which is why Timsort uses it on short runs.

    Merge sort

    def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:       # <= keeps it stable
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

    Split in half, sort each half, merge. log n levels of splitting, O(n) merge work per level. The merge step alone solves “merge two sorted lists” and “count inversions”.

    Quicksort

    import random

def quicksort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo >= hi:
        return
    p = random.randint(lo, hi)
    a[p], a[hi] = a[hi], a[p]       # random pivot to the end
    pivot, store = a[hi], lo
    for i in range(lo, hi):
        if a[i] < pivot:
            a[i], a[store] = a[store], a[i]
            store += 1
    a[store], a[hi] = a[hi], a[store]
    quicksort(a, lo, store - 1)
    quicksort(a, store + 1, hi)

    Partition around a pivot so smaller items go left and larger go right, then recurse on each side. A random pivot makes the O(n²) worst case (already-sorted input with a fixed pivot) vanishingly unlikely.

    Counting sort

    def counting_sort(a, max_val):
    count = [0] * (max_val + 1)
    for x in a:
        count[x] += 1
    return [v for v, c in enumerate(count) for _ in range(c)]

    Beats the n log n limit by not comparing at all. Use when values are small integers in a known range: grades, ages, letters.

    Binary search

    Binary search finds a boundary in O(log n) by halving the range each step. It works on anything where a yes/no question flips exactly once as you move through the range, not just sorted arrays.

    Think in boundaries

    Picture the range as answers to a question like “is a[i] >= target?”:

    index:     0  1  2  3  4  5  6
a:         1  3  3  5  8  9  12
a[i] >= 5: F  F  F  T  T  T  T
                     ^ first True is the answer

    If the answers go F…F T…T, binary search finds the first T. Framing every problem this way removes most off-by-one bugs.

    One template to remember

    def first_true(lo, hi, ok):
    # smallest x in [lo, hi] with ok(x) True;
    # returns hi + 1 if none
    hi += 1
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid          # mid might be the answer
        else:
            lo = mid + 1      # mid is definitely not
    return lo

# exact search in a sorted array
i = first_true(0, len(a) - 1, lambda i: a[i] >= target)
found = i < len(a) and a[i] == target
    • The range is half-open, [lo, hi), and the loop runs while it’s non-empty.
    • hi = mid keeps mid as a candidate; lo = mid + 1 discards it. Every step shrinks the range, so it can’t loop forever.
    • When it ends, lo == hi is the first True.

    The bisect module

    from bisect import bisect_left, bisect_right, insort

a = [1, 3, 3, 5, 8]
bisect_left(a, 3)    # 1: first index with a[i] >= 3
bisect_right(a, 3)   # 3: first index with a[i] > 3
bisect_right(a, 3) - bisect_left(a, 3)   # 2 copies of 3
insort(a, 4)         # insert keeping order (the insert itself is O(n))
bisect_left(a, x, key=lambda v: v[0])    # key= in Python 3.10+

    Common bugs

    • Infinite loop: writing lo = mid with mid = (lo + hi) // 2. When hi = lo + 1, mid equals lo and nothing changes.
    • Mixing conventions: while lo <= hi pairs with hi = mid - 1; while lo < hi pairs with hi = mid. Pick one style and stick to it.
    • Forgetting the not-found case: the returned index might be past the end or point at a different value.
    • Overflow: in Java or C++, write lo + (hi - lo) / 2. Python integers don’t overflow.

    When to suspect binary search

    • The input is sorted, or sorted after a rotation.
    • You’re asked for O(log n), or n is huge (10⁹+).
    • “Find the minimum X such that …” or “maximum X such that …”: search the answer itself.
    • A brute force tries every candidate value, and feasibility is monotonic.

    Binary search variations

    The same halving idea, applied to the shapes interviews like to use. Each one comes down to choosing the right yes/no question.

    First and last position of a value

    def span(a, t):
    lo = bisect_left(a, t)
    if lo == len(a) or a[lo] != t:
        return [-1, -1]
    return [lo, bisect_right(a, t) - 1]

    First position: first index with a[i] >= t. Last position: one before the first index with a[i] > t.

    Minimum of a rotated sorted array

    def rotated_min(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] > a[hi]:
            lo = mid + 1      # drop is to the right
        else:
            hi = mid          # mid could be the min
    return a[lo]

    Compare with the right end. If mid is bigger than the last element, the rotation point is to the right of mid.

    Search a rotated sorted array

    def rotated_search(a, t):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == t:
            return mid
        if a[lo] <= a[mid]:                    # left half sorted
            if a[lo] <= t < a[mid]: hi = mid - 1
            else:                   lo = mid + 1
        else:                                  # right half sorted
            if a[mid] < t <= a[hi]: lo = mid + 1
            else:                   hi = mid - 1
    return -1

    At least one half around mid is always properly sorted. Check whether the target falls inside that sorted half; if not, it’s in the other one.

    Binary search on the answer

    import math

def min_speed(piles, hours):
    def can_finish(speed):
        return sum(math.ceil(p / speed) for p in piles) <= hours
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if can_finish(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

    When the question is “smallest speed / capacity / days that works”, and anything above a working value also works, binary search over the values instead of an array.

    1. Bound the answer: smallest and largest possible values.
    2. Write feasible(x), usually a greedy O(n) check.
    3. Find the first x where it’s True.

    Cost: O(n · log(range)).

    A sorted 2D matrix as one array

    def matrix_has(m, t):
    rows, cols = len(m), len(m[0])
    lo, hi = 0, rows * cols - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        v = m[mid // cols][mid % cols]
        if v == t: return True
        if v < t:  lo = mid + 1
        else:      hi = mid - 1
    return False

    If each row is sorted and starts after the previous row ends, index k maps to row k // cols, column k % cols.

    Peak element

    def a_peak(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < a[mid + 1]:
            lo = mid + 1      # uphill to the right
        else:
            hi = mid
    return lo

    The array isn’t sorted, but walking uphill must reach a peak. Compare mid with its right neighbor and move toward the higher side.

    Searching real numbers

    def cube_root(x, eps=1e-9):
    lo, hi = 0.0, max(1.0, x)
    while hi - lo > eps:
        mid = (lo + hi) / 2
        if mid ** 3 < x: lo = mid
        else:            hi = mid
    return lo

    With continuous values, loop until the range is smaller than the precision you need, or for a fixed 100 iterations.

    Sliding window

    For questions about a contiguous subarray or substring, keep a window [left, right] and slide it instead of re-checking every possible range. That turns O(n²) or worse into O(n).

    Fixed-size window

    def best_sum_of_k(nums, k):
    cur = sum(nums[:k])
    best = cur
    for right in range(k, len(nums)):
        cur += nums[right] - nums[right - k]   # add new, drop old
        best = max(best, cur)
    return best

    The window length is given. Each step adds the entering element and removes the leaving one, so each update is O(1).

    Variable window: longest valid

    def longest_unique(s):
    last = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1      # jump past the repeat
        last[ch] = right
        best = max(best, right - left + 1)
    return best

    Grow the window to the right. Whenever it becomes invalid, move left until it’s valid again. Record the size while it’s valid.

    Variable window: shortest valid

    def shortest_at_least(nums, target):    # positives only
    left = total = 0
    best = float("inf")
    for right, x in enumerate(nums):
        total += x
        while total >= target:          # valid: try to shrink
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == float("inf") else best

    Grow until valid, then shrink from the left as long as it stays valid, recording the size each time.

    The general template

    left = 0
state = ...                       # counts, sum, set of what's inside
for right in range(len(a)):
    add a[right] to state
    while window is invalid:      # or: while valid, for "shortest"
        remove a[left] from state
        left += 1
    update answer using right - left + 1

    It’s O(n) because both pointers only move forward: n steps each in total.

    The “at most k” trick

    def at_most(nums, k):          # subarrays with ≤ k distinct
    count, left, ans = {}, 0, 0
    for right, x in enumerate(nums):
        count[x] = count.get(x, 0) + 1
        while len(count) > k:
            count[nums[left]] -= 1
            if count[nums[left]] == 0:
                del count[nums[left]]
            left += 1
        ans += right - left + 1     # all windows ending at right
    return ans

def exactly(nums, k):
    return at_most(nums, k) - at_most(nums, k - 1)

    “Exactly k” windows are hard to slide directly because shrinking can skip valid ones. Counting “at most k” is easy, and exactly(k) = atMost(k) − atMost(k − 1).

    When it doesn’t work

    • Negative numbers with a sum target: shrinking no longer reliably lowers the sum. Use prefix sums with a hash map instead.
    • Non-contiguous selections (subsequences): think DP or sorting.
    • Window max / min: a running variable can’t forget the old max when it leaves. Use a monotonic deque.

    Monotonic stack

    A stack whose contents stay sorted. Before pushing, pop everything that breaks the order, and each pop is the moment you learn an answer. Solves “next greater / smaller element” problems in O(n).

    Next greater element

    def next_greater(nums):
    ans = [-1] * len(nums)
    stack = []                       # indices; values decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            ans[stack.pop()] = x     # x is their next greater
        stack.append(i)
    return ans

    The stack holds items still waiting for their answer. When a bigger value arrives, everything smaller on top has found its next greater element. Store indices so you can compute distances too.

    Pick the right variant

    You wantStack keeps valuesPop while top is
    Next greater to the rightDecreasing< current
    Next smaller to the rightIncreasing> current
    Previous greater to the leftDecreasing≤ current, then top is the answer
    Previous smaller to the leftIncreasing≥ current, then top is the answer

    “Next” answers are assigned when an item is popped. “Previous” answers are read from whatever is left on top after popping. Use ≤ vs < to control how ties are handled.

    Days until warmer

    def wait_days(temps):
    ans = [0] * len(temps)
    stack = []
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            ans[j] = i - j           # distance, thanks to indices
        stack.append(i)
    return ans

    Same template as next greater, but the answer is the gap between indices.

    Largest rectangle in a histogram

    def largest_rectangle(h):
    stack, best = [], 0              # indices; heights increasing
    for i, x in enumerate(h + [0]):  # sentinel flushes the stack
        start = i
        while stack and stack[-1][1] > x:
            j, height = stack.pop()
            best = max(best, height * (i - j))
            start = j                # x can extend back to here
        stack.append((start, x))
    return best

    A bar’s rectangle ends when a shorter bar appears on the right. Popping it then gives its width. The trailing 0 forces every remaining bar to be popped.

    Monotonic deque for window max

    from collections import deque

def window_max(nums, k):
    dq, out = deque(), []            # indices; values decreasing
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()             # front slid out of window
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out

    The front is always the current window’s max. Items smaller than a newer item can never be a max again, so they’re dropped from the back.

    Why it’s O(n)

    Every index is pushed once and popped at most once, so the inner while loops do at most n pops across the entire run.

    Signals: “next greater”, “previous smaller”, “how many days until”, “span”, “visible people”, or a brute force that scans outward from every element.

    Top K

    “The k largest”, “k most frequent”, “k closest”, “kth smallest”. There are four standard approaches, and knowing their trade-offs is often what the interviewer is looking for.

    Heap: k most frequent

    from collections import Counter
import heapq

def most_frequent(nums, k):
    counts = Counter(nums)
    return heapq.nlargest(k, counts, key=counts.get)

def k_closest(points, k):       # to the origin
    return heapq.nsmallest(k, points,
                           key=lambda p: p[0]**2 + p[1]**2)

    nlargest and nsmallest keep a size-k heap internally. To keep the k largest by hand, use a min-heap and evict its root; for the k smallest, use a max-heap.

    Bucket sort: k most frequent in O(n)

    def most_frequent_linear(nums, k):
    counts = Counter(nums)
    buckets = [[] for _ in range(len(nums) + 1)]
    for val, c in counts.items():
        buckets[c].append(val)     # index = frequency
    out = []
    for c in range(len(buckets) - 1, 0, -1):
        for val in buckets[c]:
            out.append(val)
            if len(out) == k:
                return out
    return out

    No item can appear more than n times, so frequencies fit in an array of size n + 1. Walk it from high to low.

    Quickselect: kth largest in O(n) average

    import random

def kth_largest(nums, k):
    target = len(nums) - k            # index in sorted order
    lo, hi = 0, len(nums) - 1
    while True:
        p = random.randint(lo, hi)
        nums[p], nums[hi] = nums[hi], nums[p]
        store = lo
        for i in range(lo, hi):
            if nums[i] < nums[hi]:
                nums[i], nums[store] = nums[store], nums[i]
                store += 1
        nums[store], nums[hi] = nums[hi], nums[store]
        if store == target:
            return nums[store]
        if store < target: lo = store + 1
        else:              hi = store - 1

    Quicksort’s partition step, but recurse into only the side that contains the target index. Work shrinks roughly n + n/2 + n/4 + … ≈ 2n. It reorders the input in place.

    Talking through it

    1. Start with sorting: correct and easy to explain.
    2. Offer the heap to get O(n log k), and note it handles streams.
    3. Mention quickselect or bucket sort if asked for linear time.
    4. Clarify ties and whether the output order matters.

    Backtracking

    Backtracking builds candidates one choice at a time, explores where each choice leads, then undoes it to try the next. It’s how you generate every subset, combination, permutation or valid arrangement.

    The template: choose, explore, undo

    def backtrack(state, choices):
    if is_complete(state):
        results.append(state.copy())     # copy! state keeps changing
        return
    for c in choices:
        if not allowed(c, state):
            continue                     # prune
        state.append(c)                  # choose
        backtrack(state, next_choices)   # explore
        state.pop()                      # undo

    Forgetting to copy is the most common bug: appending state itself adds the same list object over and over, and it ends up empty.

    Subsets

    def subsets(nums):
    res, cur = [], []
    def go(start):
        res.append(cur[:])            # every node is an answer
        for i in range(start, len(nums)):
            cur.append(nums[i])
            go(i + 1)
            cur.pop()
    go(0)
    return res

    Passing start means you only pick later elements, so [1, 2] and [2, 1] aren’t both generated. 2ⁿ subsets, each up to n long: O(n·2ⁿ).

    Combinations of size k

    def combos(n, k):
    res, cur = [], []
    def go(start):
        if len(cur) == k:
            res.append(cur[:]); return
        need = k - len(cur)
        for i in range(start, n - need + 2):   # prune: room left
            cur.append(i)
            go(i + 1)
            cur.pop()
    go(1)
    return res

    Same as subsets but only record full-length ones. The upper bound stops early when there aren’t enough numbers left to finish.

    Permutations

    def permutations(nums):
    res, cur = [], []
    used = [False] * len(nums)
    def go():
        if len(cur) == len(nums):
            res.append(cur[:]); return
        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True; cur.append(nums[i])
            go()
            cur.pop(); used[i] = False
    go()
    return res

    Order matters, so every position can take any unused element: loop from 0, not from start. O(n·n!).

    Reuse allowed: combination sum

    def sums_to(cands, target):
    res, cur = [], []
    cands.sort()
    def go(start, remain):
        if remain == 0:
            res.append(cur[:]); return
        for i in range(start, len(cands)):
            if cands[i] > remain:
                break                  # sorted, so all later are too big
            cur.append(cands[i])
            go(i, remain - cands[i])   # i, not i + 1: reuse allowed
            cur.pop()
    go(0, target)
    return res

    Recursing with i instead of i + 1 lets the same element be picked again. Sorting enables the early break.

    Duplicates in the input

    nums.sort()
for i in range(start, len(nums)):
    if i > start and nums[i] == nums[i - 1]:
        continue          # same value already tried at this level
    ...

    Sort so duplicates sit together, then at each level skip a value equal to the one just tried. For permutations, skip when nums[i] == nums[i-1] and the earlier copy is unused.

    Constraint problems

    def queens(n):
    cols, d1, d2, count = set(), set(), set(), 0
    def go(r):
        nonlocal count
        if r == n:
            count += 1; return
        for c in range(n):
            if c in cols or r - c in d1 or r + c in d2:
                continue
            cols.add(c); d1.add(r - c); d2.add(r + c)
            go(r + 1)
            cols.remove(c); d1.remove(r - c); d2.remove(r + c)
    go(0)
    return count

    Place one piece per step and reject placements that break a rule. Keeping constraints in sets makes each check O(1). Sudoku and grid word search follow the same shape.

    Interview prep

    Interview vocabulary

    Terms interviewers use without explaining. Knowing them lets you follow hints quickly and describe your own solution precisely.

    Complexity

    Asymptotic
    Behavior as input size grows toward infinity; what Big O describes.
    Big O / Θ / Ω
    Upper bound / tight bound / lower bound on growth. In interviews “Big O” usually means the tight worst case.
    Worst / average / best case
    Cost on the most expensive input, a typical input, or the cheapest input.
    Amortized
    Average cost per operation over a long sequence, even if a few operations are expensive.
    Auxiliary space
    Extra memory beyond the input. “O(1) space” usually means auxiliary.
    In place
    Modifies the input directly, using O(1) extra memory.
    Linear / log-linear / polynomial
    O(n) / O(n log n) / O(nᵏ) for some constant k.
    Pseudo-polynomial
    Polynomial in a numeric value rather than input length, like O(n·W) knapsack.

    Algorithms

    Brute force
    Try every possibility. The baseline you state before optimizing.
    Greedy
    Take the locally best option at each step without revisiting it.
    Divide and conquer
    Split into independent subproblems, solve, combine. Merge sort.
    Dynamic programming
    Solve overlapping subproblems once and reuse the answers.
    Memoization
    Top-down DP: recursion plus a cache.
    Tabulation
    Bottom-up DP: fill a table from the smallest states upward.
    Backtracking
    Build a solution step by step, undoing choices that lead nowhere.
    Pruning
    Skipping branches that can’t produce a valid or better answer.
    Stable sort
    Equal elements keep their original order.
    Invariant
    A condition that stays true on every loop iteration, used to argue correctness.
    Sentinel
    An extra value at the boundary, like a trailing 0 or infinity, that removes edge-case checks.
    Dummy node
    A placeholder head in a linked list so the real head needs no special handling.
    Lazy deletion
    Leave stale entries in a structure and skip them when they surface.

    Data structures

    Contiguous
    Stored in one block of memory, like an array. Matters for “subarray” vs “subsequence”.
    Subarray / substring
    A contiguous slice.
    Subsequence
    Elements in original order, not necessarily adjacent.
    Collision
    Two keys hashing to the same bucket.
    Load factor
    Items divided by buckets in a hash table; drives resizing.
    Balanced tree
    A tree whose height stays O(log n).
    Sparse / dense graph
    Edges close to V / close to V².
    In-degree / out-degree
    Edges entering / leaving a node.
    Monotonic
    Only increases or only decreases.
    Immutable / hashable
    Can’t change after creation / can be used as a dict key or set member.

    The conversation

    Edge case
    An unusual input: empty, one element, all duplicates, negatives, very large values.
    Dry run
    Tracing your code by hand on an example, line by line.
    Trade-off
    Gaining one thing (speed) at the cost of another (memory, simplicity).
    Bottleneck
    The step that dominates running time; what you optimize first.
    Follow-up
    A twist after you solve it: streaming input, limited memory, multiple machines.
    Optimal
    Can’t be beaten asymptotically. Usually you must read the input once, so O(n) is often the floor.
    Idempotent
    Running it twice has the same effect as once. Common in system design questions.

    Maximum length of a concatenated string with unique characters

    MediumBacktrackingBitmaskSubsets

    The problem, in plain words

    You’re given a list of lowercase words. Choose any group of them and glue them together. The glued string is only allowed if no letter appears twice. Return the length of the longest allowed string.

    Constraints that matter: at most 16 words, each at most 26 letters, lowercase only.

    Order doesn’t change the answer, since length and “all letters unique” don’t depend on order. So this is really a question about which subset of words to pick.

    Example we’ll trace

    words  = ["ab", "cd", "bce", "xyz", "aa"]
answer = 7      # "ab" + "cd" + "xyz" = "abcdxyz"
    • "aa" can never be used: it repeats a letter by itself.
    • "bce" clashes with "ab" (shares b) and with "cd" (shares c).
    • Best is ab + cd + xyz, 7 letters. The runner-up, bce + xyz, is only 6.

    Read the constraints first

    n ≤ 16 means there are at most 2¹⁶ = 65,536 subsets. That’s small, so trying every subset is the intended solution. The input-size table on the Big O sheet says n ≈ 20 points to O(2ⁿ). The real question is how to try them efficiently and cleanly.

    Three key insights

    1. Filter bad words up front. A word with a repeated letter inside it (like "aa") can never be part of an answer. Removing it first avoids the most common bug in this problem.
    2. Each word is take or skip. That’s the subsets pattern, so use backtracking (see the Backtracking sheet). Prune a branch as soon as a word clashes with what you already have.
    3. Check clashes in O(1) with a bitmask. Turn each word into a 26-bit number, one bit per letter. Two words share a letter exactly when a & b != 0. Combining them is a | b.

    Bitmask in 30 seconds

    Bit 0 means “contains a”, bit 1 means “contains b”, and so on up to bit 25 for z.

    WordBits (… e d c b a)Value
    "ab"000113
    "cd"0110012
    "bce"1011022
    3 & 12 == 0     # "ab" and "cd" share nothing → compatible
3 | 12 == 15    # combined letters {a, b, c, d}
3 & 22 == 2     # bit 1 set → both contain "b" → clash

    With sets you’d write used.isdisjoint(word_set) and used | word_set. Same logic; the bitmask version is just faster and uses one integer.

    Solution: backtracking with bitmasks

    def maxLength(arr):
    # 1) keep only words with no repeated letters, as (mask, length)
    words = []
    for w in arr:
        if len(set(w)) != len(w):
            continue                    # e.g. "aa" can never be used
        mask = 0
        for ch in w:
            mask |= 1 << (ord(ch) - ord("a"))
        words.append((mask, len(w)))

    best = 0

    # 2) try every compatible subset
    def dfs(start, used, length):
        nonlocal best
        best = max(best, length)        # every node is a valid string
        for i in range(start, len(words)):
            mask, n = words[i]
            if (used & mask) == 0:      # no shared letters
                dfs(i + 1, used | mask, length + n)

    dfs(0, 0, 0)
    return best

    How to read it

    • used is the set of letters already in the string, stored as a bitmask.
    • length is tracked separately so you never count bits.
    • The loop from start is the subsets template: only look at later words, so each group is tried once.
    • A clashing word is simply skipped. That’s the pruning.
    • best updates at every call, because every partial choice is already a valid string.

    Trace on the example

    After filtering, the words are ab, cd, bce, xyz. Each line is one dfs call with the letters used so far.

    start  {}                      len 0
├─ ab  {a,b}                   len 2
│  ├─ cd  {a,b,c,d}            len 4
│  │  ├─ bce   clash (b, c)    skipped
│  │  └─ xyz {a,b,c,d,x,y,z}   len 7   ← best
│  ├─ bce   clash (b)          skipped
│  └─ xyz {a,b,x,y,z}          len 5
├─ cd  {c,d}                   len 2
│  ├─ bce   clash (c)          skipped
│  └─ xyz {c,d,x,y,z}          len 5
├─ bce {b,c,e}                 len 3
│  └─ xyz {b,c,e,x,y,z}        len 6
└─ xyz {x,y,z}                 len 3

    Clashes cut whole branches. On real inputs most subsets are never visited.

    Alternative: build all reachable sets iteratively

    def maxLength(arr):
    combos = [(0, 0)]                   # (mask, length)
    for w in arr:
        if len(set(w)) != len(w):
            continue
        m = 0
        for ch in w:
            m |= 1 << (ord(ch) - 97)
        for used, n in combos[:]:       # copy: don't loop over new items
            if (used & m) == 0:
                combos.append((used | m, n + len(w)))
    return max(n for _, n in combos)

    Same idea without recursion: keep every valid combination built so far, and for each new word try adding it to each of them. Easy to explain, and it avoids recursion limits. It stores up to 2ⁿ entries, so it uses more memory than the DFS.

    Complexity

    • Time: O(n · 2ⁿ) in the worst case. There are at most 2ⁿ valid subsets (calls), and each call loops over up to n words with O(1) bit checks. For n = 16 that’s about a million steps. Preprocessing adds O(total letters).
    • Space: O(n) for the recursion depth and the list of masks.
    • A useful extra bound: a valid string has at most 26 letters, so each path picks at most 26 words, and many branches die early.

    Common bugs

    • Forgetting words like “aa”. If you only check clashes between words, a word that repeats its own letter slips through.
    • Python operator precedence. used & mask == 0 means used & (mask == 0). Always write (used & mask) == 0.
    • Only updating the answer at the leaves. With the loop-from-start template, update at every call.
    • Building real strings in the recursion. Concatenating and copying strings works, but it’s slower and messier than passing a mask and a length.

    How to say it in the interview

    “There are at most 16 words, so at most 65 thousand subsets, which means trying every subset is fine. I’ll first drop any word that repeats a letter by itself, since it can never be used. Then I’ll backtrack: for each word I either skip it or take it if it shares no letters with what I’ve picked. To make that check fast, I’ll store each word as a 26-bit mask, so a clash is just and not equal to zero and adding the word is or. I track the best length at every step. That’s O(n · 2ⁿ) time and O(n) space.”

    Likely follow-ups

    • Return the string, not the length. Also pass the list of chosen indices, and save a copy when you find a new best.
    • What if there were many more words? Many subsets produce the same set of letters. Keep a set of distinct masks in the iterative version; there can’t be more distinct masks than the number of letter subsets that are actually reachable, which is far less than 2ⁿ in practice.
    • Uppercase and lowercase? Use 52 bits. Python integers have no fixed size, so the code barely changes.
